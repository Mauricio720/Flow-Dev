# ADR-007: Bind the existing Issue Author to an operation-scoped context broker

## Status

Accepted

## Date

2026-10-01

## Context

The existing Dev_Control Issue Author has a canonical result contract and authenticated final-result route. Its tools read Dev_Control's filesystem or use global GitHub credentials, neither of which satisfies ADR-004. Its provenance validator can accept a line range from the wrong file. Mastra 1.72.0 supports per-request RequestContext, verified in installed documentation and types.

## Decision

Keep Issue Author in Dev_Control and add a versioned, service-authenticated Flow Dev invocation route. Reuse its authoring instructions, model and canonical draft, with task-scoped tools that call a protected Flow Dev context broker. The broker derives the repository and author from the active persisted operation, revalidates access for each lookup, and obtains the author's GitHub token only inside Flow Dev. Repository selectors and filesystem roots are not model-controlled inputs.

Give each worker execution a short-lived, random capability stored only as a hash. Pass the capability through Mastra RequestContext to the tool client, never as model content or telemetry. Return actual activity/evidence in the final generation envelope, including genuine empty and unavailable outcomes. Final delivery with polling satisfies the PRD; no invented progress or SSE infrastructure is needed.

Validate every source against its repository identity, actual path/Issue identity, commit and returned line range. Previously retrieved evidence can survive refinement only as an unchanged historical evidence binding. Changed wording loses its verified badge until explicitly grounded again. Show refinement proposals as a field diff; the author chooses the changes to apply to the saved revision, preserving unrelated manual edits.

## Alternatives Considered

### Alternative 1: Call the current message-only route unchanged

- **Description**: Send conversation to `/issue-author` using existing tools and global context.
- **Pros**: Small HTTP adapter.
- **Cons**: Wrong repository, credential bypass and no real activity contract.
- **Why rejected**: Violates ADR-004.

### Alternative 2: Embed Mastra in the Flow Dev API package

- **Description**: Copy or import the agent runtime and skills into the monorepo.
- **Pros**: Fewer network boundaries.
- **Cons**: Duplicates ownership of the existing agent and couples Next.js/backend deployments to the sibling's framework/runtime.
- **Why rejected**: The existing agent service is the established integration point; a versioned route reuses it directly.

### Alternative 3: Pass the user's GitHub token to Dev_Control

- **Description**: Tools access GitHub directly using a token in request context.
- **Pros**: No tool callback endpoint.
- **Cons**: Enlarges the credential boundary and cannot independently recheck current Flow Dev membership at each lookup.
- **Why rejected**: An operation-scoped broker keeps credentials and permission rules with their existing owner.

## Consequences

### Positive

- One existing agent continues to own Issue authoring.
- Tokens remain in Flow Dev and sources have verifiable task-bound provenance.

### Negative

- Both repositories require coordinated contract changes and a reachable private callback origin.
- Activity appears when the result completes, rather than as live tool rows.

### Risks

- Dev_Control's current eval/readiness evidence is incomplete; the new protocol and real project tools need fresh verification.
- Mastra built-in routes and traces must not expose private conversation or capabilities; isolate the service and redact content telemetry.
- Unrelated edits cannot be guaranteed by model instructions alone; apply only author-selected field changes from the proposal.

## Implementation Notes

Use existing Mastra APIs after checking installed docs, load the sibling mastra skill, and register new tools/routes in src/mastra/index.ts. Keep the existing `/issue-author` contract for other callers; the Flow Dev route never falls back to its local/global tools.
