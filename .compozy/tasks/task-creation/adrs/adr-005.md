# ADR-005: Use Groq Whisper V3 Turbo for reviewed dictation

## Status

Accepted

## Date

2026-10-01

## Context

ADR-003 requires working microphone input across desktop Chrome, Edge, Firefox and Safari, Android Chrome and iOS Safari. The repository has no transcription implementation. The user compared hosted prices and using an already contracted Magalu VPS, then explicitly selected Groq — Whisper V3 Turbo.

## Decision

Capture audio with getUserMedia and MediaRecorder. After Stop, upload the completed recording to a protected Flow Dev multipart endpoint; the backend calls Groq's `/openai/v1/audio/transcriptions` with `model=whisper-large-v3-turbo`, `language=pt` and `response_format=json`. Append the completed transcript to the originating editable input exactly once. Only manual Send accepts a message. Cancel restores the input captured before recording and fences late results.

Limit one capture to 180 seconds and 10 MiB of encoded audio. Negotiate WebM/Opus or MP4/AAC using MediaRecorder.isTypeSupported; retain the actual supported container. Keep audio in browser/server memory only and dispose it after completion, cancellation or timeout. Enable Groq Zero Data Retention for transcription before production, disable audio/request-body logging, and disclose remote processing before first capture. Do not claim that local cleanup alone controls provider retention.

## Alternatives Considered

### Alternative 1: OpenAI GPT-4o Mini Transcribe

- **Description**: Use the same post-capture interaction with OpenAI transcription.
- **Pros**: Managed audio API; no model hosting.
- **Cons**: Higher published estimated audio cost than Groq Turbo at research time.
- **Why rejected**: The user selected Groq after comparing costs.

### Alternative 2: Whisper on the existing VPS

- **Description**: Host a CPU transcription service on the contracted Magalu VPS.
- **Pros**: No per-request provider charge; control of processing infrastructure.
- **Cons**: CPU/RAM contention, maintenance, and hardware-dependent latency and model quality.
- **Why rejected**: The user chose the managed Groq service after discussing this alternative.

### Alternative 3: Browser SpeechRecognition only

- **Description**: Delegate recognition to the native browser API.
- **Pros**: Little backend integration.
- **Cons**: Uneven browser availability cannot meet ADR-003's required matrix.
- **Why rejected**: Conflicts with the accepted compatibility requirement.

## Consequences

### Positive

- Dictation has one provider contract across the required browsers.
- The backend keeps the provider key private; authors review text before it becomes intent.

### Negative

- Authors wait for transcription after Stop; live partial transcripts are not required.
- Voice depends on connectivity and the configured Groq account's rate limits.

### Risks

- Incorrect technical terms require editable review and a pt-BR quality check.
- Provider retention settings must match the first-use disclosure. Groq documents exceptional reliability/abuse retention of up to 30 days unless ZDR is enabled.
- Container support and real microphone behavior require device verification, including real Safari/iOS; Playwright emulation alone is insufficient.

## Implementation Notes

Use a small TranscriptionGateway contract in the existing API package and a Groq HTTP implementation. Do not introduce a local speech server, streaming transport or automatic provider fallback. Current published pricing is US$0.04/hour with a ten-second minimum billed duration; this is research context, not a fixed product promise.
