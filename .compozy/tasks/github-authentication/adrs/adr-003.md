# ADR-003: Explicit initial administrator provisioning

## Status

Accepted

## Date

2026-09-30

## Context

Project assignments require an administrator. The application has no account or role management yet, and the user wants administrator admission to be controlled through an internal hard-coded script for this feature. General control over which GitHub accounts may enter is deferred.

## Decision

Initial administrator accounts are explicitly provisioned by an internal script that names the intended GitHub identities. The first person to sign in does not automatically become an administrator. Administrators can manage user-to-project assignments in Flow Dev and may access all existing projects. Changing who is an administrator remains an internal provisioning action for now; this feature does not provide administrator role management in the UI.

## Alternatives Considered

### Alternative 1: First sign-in becomes administrator

- **Description**: The first GitHub account to complete sign-in receives the administrator role.
- **Pros**: No provisioning step.
- **Cons**: Makes privilege depend on timing and allows an unintended account to claim it.
- **Why rejected**: The user chose explicit script-based provisioning.

### Alternative 2: Every signed-in account can manage assignments

- **Description**: Remove the administrator role for the initial release.
- **Pros**: No bootstrap dependency.
- **Cons**: Any GitHub account could grant itself access to projects.
- **Why rejected**: Contradicts administrator-delimited project access.

## Consequences

### Positive

- Administrator privileges are assigned deliberately.
- A project-assignment workflow can exist without adding a role-management interface.

### Negative

- Provisioning or replacing an administrator requires an internal operation.
- The release needs at least one intended administrator identity before the assignment workflow is useful.

### Risks

- Incorrect identity matching could grant the wrong account privileges; provisioning must resolve the intended GitHub identity unambiguously and be auditable.

## Implementation Notes

The TechSpec will specify the script and stable identity matching. The script must not contain credentials or secrets. The specific initial administrator accounts are deployment configuration, not product behavior.
