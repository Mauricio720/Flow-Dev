# ADR-005: Keep repository artifacts and the Flow Dev review synchronized without Git publication

## Status

Accepted

## Date

2026-10-05

## Context

Compozy works with a local repository workspace, while users review the work through Flow Dev. The user chose both repository files and application visibility, without automatic commit or push.

## Decision

Save the generated document package under `.compozy/tasks/<slug>/` in the checkout bound to the work item's project. Expose the matching saved revision and its provenance in Flow Dev, including the applicable companion documents. A reviewed approval always refers to the exact captured document package, not whichever files later happen to occupy the paths.

A stage is review-ready only when the required outputs are complete and available consistently to the repository workflow and the application's review experience. Partial writes, capture failures, and externally changed files cannot silently become an approved replacement. Protect unrelated files and specification packages from collisions.

This feature creates specification files only. It does not commit, push, create a PR, or change the published Issue. A later publishing workflow is outside this PRD.

## Alternatives Considered

### Alternative 1: Store outputs only in Flow Dev

- **Description**: Treat the application as the only artifact destination.
- **Pros**: Avoids coordinating displayed documents and repository files.
- **Cons**: Does not deliver the selected repository workflow for later task execution.
- **Why rejected**: The user chose checkout artifacts plus Flow Dev visibility.

### Alternative 2: Commit or publish a document PR after approval

- **Description**: Couple stage approval to Git publication.
- **Pros**: Shares files through an external repository workflow immediately.
- **Cons**: Adds a publishing action and policy beyond the selected scope.
- **Why rejected**: The user chose no automatic commit or push.

## Consequences

### Positive

- The reviewed documents remain usable by subsequent repository workflows.
- Approval does not imply an external publication side effect.

### Negative

- The integration must identify and preserve the relationship between repository files and reviewed versions.

### Risks

- Concurrent runs or external file edits could overwrite a reviewed package. Require scope isolation, collision handling, and explicit conflict visibility.
- An unavailable checkout could be mistaken for a missing specification. Preserve recorded artifacts and explain the operational blocker.

## Implementation Notes

Checkout provisioning, isolation, revision retention, and consistency mechanisms belong to the TechSpec. This decision does not prescribe branches, worktrees, tables, or a new workspace-management screen.
