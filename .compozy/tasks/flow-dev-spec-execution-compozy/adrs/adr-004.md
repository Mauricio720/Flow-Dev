# ADR-004: Preserve context across interactive runs, cancellation, and retry

## Status

Accepted

## Date

2026-10-05

## Context

The brief requires users to follow agent activity and answer questions and permission requests inside Flow Dev. The existing product already preserves accepted work and restricts mutations to the author. The user chose cancellation and retry with saved context retained.

## Decision

Keep execution progress, user-visible agent communication, interactions, saved artifacts, and accepted responses associated with the existing work item and stage. Authorized readers follow the same recorded progress; only the author can answer, approve permissions, request changes, cancel, retry, or approve an artifact.

An unanswered interaction waits for explicit author input without inferring an answer or approval. A terminal runtime failure is shown as a failure requiring recovery, not as an answered question. Cancellation requests a stop, reports its confirmation or uncertainty, and preserves saved context. An explicit new attempt reuses applicable saved decisions and artifacts; it does not automatically repeat previously resolved interactions or approve previous permission grants for unrelated actions.

Refresh, reconnection, duplicate submissions, and delayed events must not create competing attempts or regress the current state. A retry starts only once the preceding attempt's status is known well enough to prevent competing work. Partial outputs remain distinguishable from review-ready documents.

## Alternatives Considered

### Alternative 1: Always restart with no prior context

- **Description**: Discard the previous stage attempt's decisions and outputs on retry.
- **Pros**: Simplifies what a new attempt receives.
- **Cons**: Repeats answered questions and loses useful work.
- **Why rejected**: The user chose preservation of saved context.

### Alternative 2: Omit cancellation or treat browser navigation as cancellation

- **Description**: Make accepted work uninterruptible or tie it to the open page.
- **Pros**: Fewer explicit lifecycle actions.
- **Cons**: Removes author control or loses work unexpectedly.
- **Why rejected**: The user chose explicit cancellation, and existing durable-work behavior separates navigation from execution.

## Consequences

### Positive

- The author can supervise long-running work without remaining on the page.
- Questions, interruptions, and retries remain understandable and attributable.

### Negative

- Execution and interaction reconciliation are necessary across service interruptions.

### Risks

- A replayed answer, late completion, or lost cancellation response could misrepresent progress. Associate every visible event and action with its stage and attempt, and show uncertainty until reconciled.
- Agent permission requests could exceed the Spec scope. Apply configured boundaries independently of the author's response.

## Implementation Notes

Session reuse versus replacement, event transport, durable storage, stop verification, and orphaned-interaction recovery belong to the TechSpec. Official session documentation describes relevant capabilities, but this integration has not been exercised.
