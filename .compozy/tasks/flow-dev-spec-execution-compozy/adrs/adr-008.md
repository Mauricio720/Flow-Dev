# ADR-008: Persist a separate Spec lifecycle and deliver a cursor-based live projection

## Status

Accepted

## Date

2026-10-05

## Context

Existing task operations and receipts have SQL CHECK constraints tied to authoring/publication/planning. Existing activity reads stop at 500 records. Approved planning has immutable database triggers. Compozy durable events include internal reasoning that must not reach the application.

## Decision

Add dedicated `task_spec_*` tables for workflow/stage state, attempts, command receipts, interactions, events, packages and documents. Preserve the original task publication status and immutable planning decision. Use transactional receipts, optimistic workflow versions, scoped row locks, worker lease fences and one active attempt per work item.

Persist an allowlisted, sanitized projection of runtime activity with a separate monotonically increasing Flow Dev sequence. Consume Compozy raw persisted SSE with its own durable cursor; never forward provider streams directly to browsers. Exclude thought events, secrets, raw provider payloads and host paths.

Expose tRPC queries for current state, paged events, package metadata and documents, plus explicit mutations for author commands. Poll saved incremental events every second while visible and active; use five seconds while waiting/reviewing and thirty seconds in terminal states. Every request revalidates access. Polling delivers real activity while work runs, uses existing transport infrastructure, and avoids introducing a second browser authentication/streaming surface.

Command outcomes can be accepted, applied, rejected or awaiting reconciliation. A pending reply is not delivered merely because Flow Dev saved it. Runtime loss leaves uncertain state until reconciliation proves the outcome. Stop verification, attempt fencing and current-package comparison decide cancel/complete races.

## Alternatives Considered

### Alternative 1: Extend task status and reuse all task operation states

- **Description**: Extend task status and reuse all task operation states.
- **Pros**: Fewer new tables.
- **Cons**: Conflates retained publication with a long interactive lifecycle and requires unrelated constraint changes.
- **Why rejected**: Dedicated Spec state preserves existing behavior.

### Alternative 2: Proxy Compozy SSE directly to each browser

- **Description**: Proxy Compozy SSE directly to each browser.
- **Pros**: Lower nominal latency.
- **Cons**: Leaks runtime semantics and complicates authorization, redaction, replay and fan-out.
- **Why rejected**: Persisted incremental queries satisfy live supervision with the existing tRPC client.

## Consequences

### Positive

Reuses proven persistence and access patterns while supporting durable observation and safe restarts.

### Negative

Polling adds read load and up to one polling interval of presentation latency; normalization adds persistence cost.

### Risks

Never use only an event cursor for lifecycle authority; snapshots and pending interactions remain independently readable. Gap detection must prevent silent replay loss.

## Implementation Notes

See the TechSpec for concrete interfaces, ownership, limits, recovery and verification gates. This ADR specifies the target implementation; it does not claim the integration is deployed.
