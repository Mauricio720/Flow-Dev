# ADR-003: Project catalog is the gateway to project menus

## Status

Accepted

## Date

2026-09-30

## Context

The current home page opens directly in a simulated issue workspace. The user wants a Supabase-inspired project selection experience before entering project menus. The authentication PRD already defines assigned-project visibility and administrator-wide visibility; this feature must make those rules visible in the product.

## Decision

After sign-in, users land in a project catalog. Selecting an available project enters its project-specific shell, where the active project and its GitHub repository are visible and the existing menus live. Administrators create projects by selecting a repository they can access and setting a project name; only administrators may edit project details. The catalog uses Flow Dev's visual language while taking the project-first hierarchy from Supabase. Task management remains a separate feature.

## Alternatives Considered

### Alternative 1: Keep the issue workspace as the home page

- **Description**: Add a project selector within the current workspace.
- **Pros**: Fewer navigation changes.
- **Cons**: Makes project context easy to miss and conflicts with the requested entry order.
- **Why rejected**: The user explicitly wants projects before the menus.

### Alternative 2: Let every signed-in user create projects

- **Description**: Offer project creation in the catalog to all accounts.
- **Pros**: Faster self-service onboarding.
- **Cons**: Bypasses administrator-managed project access and ownership expectations.
- **Why rejected**: The user chose administrator-only creation and management.

### Alternative 3: Include task management now

- **Description**: Deliver project selection, repository connection, and project tasks together.
- **Pros**: A project has immediate internal work items.
- **Cons**: Expands this feature beyond the requested first step.
- **Why rejected**: The user explicitly reserved tasks for another PRD.

## Consequences

### Positive

- Users know which project's code and later tasks or issues they are using.
- The no-project and repository-access states have natural places in the journey.
- Existing menus can be entered under an explicit project context.

### Negative

- Entering a menu takes an additional project-selection step when no prior valid selection can be resumed.
- The existing direct-to-workspace demo navigation must be adapted to the new journey.

### Risks

- A deep link could bypass the catalog; project access still must be enforced on entry and action.
- The visual reference could obscure Flow Dev identity; use the existing product design tokens and accessibility rules.

## Implementation Notes

The TechSpec will define routes and component boundaries. The project catalog's behavior is part of this decision; a specific layout implementation is not.
