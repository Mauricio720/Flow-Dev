# ADR-004: Present real planning artifacts and stop at route approval

## Status

Accepted

## Date

2026-10-05

## Context

The source describes a longer development lifecycle but explicitly limits this delivery to published Issue → planning → approved route. It requires a Human View rather than raw Markdown, JSON, or technical logs as the main experience.

## Decision

Present the PlanningDecision as named fields for complexity, summary, recommended route, selected route, reasons, uncertainties, agent attribution, and review or approval status. Keep the published Issue separately inspectable and distinguish lifecycle progress from the authoring conversation.

Represent actual lifecycle progress only through planning. Describe Direct execution, Tech Spec, and PRD as possible next routes without creating their artifacts, starting their agents, or showing them as running. Approval records the chosen route locally in Flow Dev and stops there. Raw technical content, if exposed, is secondary detail.

## Alternatives Considered

### Alternative 1: Show the provider response as a conversation message

- **Description**: Render planning primarily as raw JSON or Markdown alongside authoring messages.
- **Pros**: Requires little transformation of provider output.
- **Cons**: Makes state, rationale, choices, and artifacts harder to distinguish.
- **Why rejected**: The source explicitly requires a structured Human View.

### Alternative 2: Start the next agent immediately after approval

- **Description**: Approval triggers PRD writing, Tech Spec writing, or code execution.
- **Pros**: Continues the complete lifecycle automatically.
- **Cons**: Adds capabilities explicitly excluded from this delivery and implies executable downstream support.
- **Why rejected**: The source stops this delivery at route approval.

## Consequences

### Positive

- Users understand what happened, who performed it, what was produced, and what remains a human decision.
- The interface does not promise unavailable development capabilities.

### Negative

- An approved route is recorded but cannot be executed from this delivery.

### Risks

- Route illustrations may resemble live progress. Label them as the recommended or chosen route and keep them distinct from the actual lifecycle.
- Existing design guidance describes only the draft as an artifact container. The implementation must evolve that guidance consistently with the new planning artifact rather than hide planning in raw text.

## Implementation Notes

Preserve pt-BR interface language and existing accessibility and design conventions. Exact layouts and component choices belong to the TechSpec and implementation.
