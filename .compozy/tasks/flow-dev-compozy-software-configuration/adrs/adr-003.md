# ADR-003: Connect Codex with ChatGPT in-app without exposing credentials

## Status

Accepted

## Date

2026-10-06

## Context

The operator uses a ChatGPT subscription with Codex and does not have OpenAI API credits. The current host-side Codex login works, but a containerized worker cannot safely assume access to the operator's entire default Codex directory. The user chose a complete connection and reconnection experience in the Software menu.

## Decision

Support a browser-led Codex connection using ChatGPT subscription authentication, with visible connection status, reconnection, and disconnection. The application never asks the administrator for an OpenAI API key to use this path. Credential material remains server-side, never appears in browser responses or task artifacts, and is scoped to the Compozy execution environment. The Software area can hold multiple supported execution connections; unsupported or incomplete connections are visible as unavailable rather than selectable.

## Alternatives Considered

### Alternative 1: Require an OpenAI API key

- **Description**: Replace the existing ChatGPT subscription path with usage-based API authentication.
- **Pros**: Straightforward server credential provisioning.
- **Cons**: Requires separate billing and violates the operator's stated constraint.
- **Why rejected**: The user explicitly needs to keep using the subscription-backed Codex login.

### Alternative 2: Show terminal instructions only

- **Description**: Keep login outside Flow Dev and show status in the menu.
- **Pros**: Less application-owned connection state.
- **Cons**: Leaves the core setup task outside the requested Software experience.
- **Why rejected**: The user selected full connection and reconnection through the menu.

## Consequences

### Positive

- Administrators can establish and recover the subscription-backed connection without handling an API key.
- Task authors only see ready, non-secret execution options.

### Negative

- A connection may need reauthorization when the account session expires or is revoked.

### Risks

- Authentication state must not be confused with runtime readiness; a connected account does not prove that the image, isolation, or agent compatibility is ready.

## Implementation Notes

The TechSpec must validate the chosen browser-led login mechanism against the pinned Compozy/Codex runtime, including headless or remote hosts, refresh, revocation, and credential isolation.
