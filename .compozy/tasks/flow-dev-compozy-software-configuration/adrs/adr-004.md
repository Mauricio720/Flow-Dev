# ADR-004: Use pinned CompozyOS control contracts and catalog

## Status

Accepted

## Date

2026-10-06

## Context

Flow Dev needs to inspect provider capabilities, authenticate connections, create sessions, and resolve worktrees. The installed `compozy` command is v0.2 and does not represent CompozyOS. The project's Spec runner pins CompozyOS `v0.3.0-beta.29`. Its external MCP relay publishes only a workspace-bound Host API subset; provider bootstrap, model catalog, and worktree administration are outside that projection.

## Decision

Use the pinned CompozyOS 0.3 HTTP/UDS API as the server integration contract for provider probes, model catalog, worktrees, and session execution. Keep the runtime release and OpenAPI digest pinned and fail closed on mismatch. `compozy mcp serve` may be connected separately for trusted workspace-scoped operator work, but Software does not require or assume it. Model and reasoning choices come from the runtime catalog, then pass live provider negotiation at execution. The local v0.2 CLI is never used as a compatibility source.

## Alternatives Considered

### Use the MCP relay as the only integration

- **Pros**: One external client protocol.
- **Cons**: The documented projection excludes required administrative and worktree methods and grants its client operator authority over the selected workspace.
- **Why rejected**: It cannot satisfy the complete feature or its trust boundaries.

### Query the locally installed CLI

- **Pros**: Easy to prototype.
- **Cons**: The installed binary is deprecated v0.2 and its command/schema contract differs from v0.3.
- **Why rejected**: Results would misrepresent the target runtime.

## Consequences

### Positive

- Flow Dev presents capabilities that the pinned runtime actually exposes.
- MCP remains available for its intended trusted workspace-bound use.

### Negative

- The integration must maintain explicit HTTP/UDS adapters and pinned schema checks.

### Risks

- Beta API changes require a deliberate pin update and contract verification before deployment.

## Implementation Notes

The existing Spec worker already uses a pinned CompozyOS control path. Extend that adapter, not a second MCP daemon. Keep Host API credentials/socket access server-side.
