# ADR-001: Delete linked issues from Flow Dev and GitHub

## Status

Accepted

## Date

2026-10-13

## Context

Flow Dev keeps an issue's authoring or assigned-work history after the GitHub Issue is created or imported. A local-only removal would leave the GitHub Issue visible, while a GitHub-only removal would leave a misleading Flow Dev work item. The user requested deletion in both places for both Flow Dev-created and imported issues.

## Decision

One explicit deletion action removes the GitHub Issue and its Flow Dev issue record and history. A saved issue with no GitHub publication attempt or with confirmed noncreation is removed only from Flow Dev. Imported issues follow the same deletion journey as Flow Dev-created issues, including Ready queue Issues that have no local work item yet. The action is permanent and requires an explicit confirmation that names the issue and its repository.

The user sees completion only after the required destinations are confirmed absent. A confirmed already-deleted GitHub Issue counts as absent; an unverified provider response does not.

## Alternatives Considered

### Alternative 1: Remove only the Flow Dev work item

- **Description**: Hide or delete the local record while leaving GitHub unchanged.
- **Pros**: Works without GitHub deletion permission.
- **Cons**: Leaves the Issue and its board presence in GitHub.
- **Why rejected**: The user explicitly requested deletion in both systems.

### Alternative 2: Restrict deletion to Flow Dev-created issues

- **Description**: Leave imported issues to be deleted directly in GitHub.
- **Pros**: Smaller scope.
- **Cons**: Gives two otherwise identical work items different deletion behavior.
- **Why rejected**: The user explicitly included both origins.

## Consequences

### Positive

- The issue disappears from both product surfaces after confirmed success.
- Drafts and imported issues have a coherent deletion action.

### Negative

- Published and imported issues require an external permission and response.
- Deletion cannot be undone through Flow Dev.

### Risks

- GitHub can reject deletion or return an uncertain result; the local record must remain available for recovery.
- A publication in flight can create an Issue during deletion; its outcome must be established before success is reported.

## Implementation Notes

The TechSpec decides the provider mutation, local record lifecycle, and recovery mechanism. The product contract is confirmed absence at both destinations.
