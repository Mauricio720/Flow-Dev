# ADR-003: Require local authority and confirmed GitHub deletion

## Status

Accepted

## Date

2026-10-13

## Context

Flow Dev authorship, Flow Dev administration, project access, and GitHub repository administration are separate permissions. GitHub permanently deletes Issues only for repository administrators or owners, subject to organization settings. Deletion can fail after the local work has been stopped.

## Decision

An issue's author or a Flow Dev administrator with current project access may initiate deletion. For a GitHub-linked issue, the initiating person's GitHub identity must also be allowed to delete it. An imported issue uses its GitHub author as the author for this policy. A Flow Dev role never bypasses GitHub authorization.

If GitHub denies deletion, is unavailable, or returns an uncertain result, retain the local issue and show a reason and a retry path. A later retry resumes deletion without restarting stopped work or duplicating external actions. If the GitHub Issue is confirmed already absent, complete the local removal.

## Alternatives Considered

### Alternative 1: Let every project member delete

- **Description**: Treat project access as sufficient local authority.
- **Pros**: Simple availability.
- **Cons**: Allows one member to remove another's issue history.
- **Why rejected**: The user selected author or administrator access.

### Alternative 2: Delete locally after any GitHub failure

- **Description**: Treat remote deletion as best effort.
- **Pros**: Clears the Flow Dev list immediately.
- **Cons**: Leaves an Issue in GitHub with no local recovery context.
- **Why rejected**: The user chose to retain the local issue and allow retry.

## Consequences

### Positive

- The person who initiated deletion can see which destination remains and retry safely.
- Missing GitHub permission does not cause silent local data loss.

### Negative

- A Flow Dev author without GitHub administration cannot complete linked-Issue deletion.
- Imported-issue authorship must be established before author access is offered.

### Risks

- GitHub may mask a permission failure as a missing resource; absence must be verified before local deletion.
- A stale issue or project identity could target the wrong resource; use the confirmed linked identity.

## Implementation Notes

The TechSpec defines authorization checks, identity verification, and the recoverable result contract. Provider tokens remain scoped to the initiating user.
