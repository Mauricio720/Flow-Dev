# ADR-004: Preserve code artifacts associated with a deleted issue

## Status

Accepted

## Date

2026-10-13

## Context

Flow Dev can create or reuse a local worktree for an issue and can open a GitHub Pull Request from its branch. Those artifacts can contain human edits or published code review independent of the Issue. The user requested that they remain after Issue deletion.

## Decision

Deleting an issue does not delete a local worktree, Git branch, or Pull Request. Before final confirmation, explain that those artifacts may remain. Stop active Flow Dev work, but do not erase its code output or close or delete an existing Pull Request. Flow Dev removes the issue's own records and views after confirmed deletion.

## Alternatives Considered

### Alternative 1: Delete worktrees with the issue

- **Description**: Automatically clear local issue checkout folders.
- **Pros**: Frees local space.
- **Cons**: Can destroy uncommitted work.
- **Why rejected**: The user chose to preserve worktrees.

### Alternative 2: Delete branches and Pull Requests too

- **Description**: Extend cleanup to all GitHub code artifacts.
- **Pros**: Removes more related objects.
- **Cons**: Discards review and code history that may have other collaborators.
- **Why rejected**: The user chose to preserve branches and Pull Requests.

## Consequences

### Positive

- Issue deletion does not silently destroy code or review work.

### Negative

- Preserved artifacts can outlive the Flow Dev record that originally linked to them.

### Risks

- Users may expect full cleanup from the word “delete”; the confirmation must name what remains.

## Implementation Notes

The TechSpec must distinguish issue-owned data from preserved checkout and GitHub code artifacts during cleanup.
